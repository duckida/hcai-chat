# AGENTS.md - Coding Agent Guide for HCAI Chat

This document provides an overview of the codebase, architecture, and development environment for coding agents working on the **HCAI Chat** application.

## Project Overview
HCAI Chat is a modern AI-driven chat interface built with **Next.js (App Router)**, featuring real-time streaming, web search integration, and an "Artifacts" system for displaying structured HTML content generated by the AI. It connects to the Hack Club AI proxy (`https://ai.hackclub.com/proxy/v1`).

## Tech Stack
- **Framework**: Next.js 16+ (App Router)
- **Styling**: Tailwind CSS v4, Shadcn UI, Lucide React, Framer Motion
- **Language**: JavaScript (ESM), JSX for components
- **API/Backend**: Next.js API Routes (Serverless)
- **Search Integration**: Exa AI via Hack Club proxy
- **Streaming**: AI SDK v6 (`ai` + `@openrouter/ai-sdk-provider`)
- **Content Rendering**: Streamdown (with cjk, code, math, mermaid plugins)
- **Code Quality**: Biome (Linting/Formatting)
- **Testing**: Vitest + React Testing Library + jsdom

## Project Structure

### Core Directories
- `src/app/`: Next.js App Router pages and API routes.
  - `api/chat/route.js`: Handles streaming chat completions using `streamText` from the AI SDK. Supports tool calls via native multi-step loop. Also handles non-streaming title generation when `stream: false`.
  - `api/exa/route.js`: Proxy for Exa web search capabilities. Endpoints: search, findSimilar, contents, answer.
  - `api/models/route.js`: Fetches and filters available AI models from Hack Club AI proxy, filtering to text-only output modalities.
  - `api/tools/route.js`: Standalone tool execution endpoint. POST executes a tool (web_search, javascript_calculator); GET lists available tools.
  - `api/upload/route.js`: Proxies file uploads to bucky.hackclub.com with validation (type, size, filename sanitization).
  - `search/page.js`: Dedicated search page that parses `?q=` and `?search=true` params and renders the main `Home` component with an initial query.
  - `layout.js`: Root layout with Inter font, globals.css, katex CSS, dark mode FOUC prevention script, and AppWrapper.
  - `page.js`: Main chat application entry point and state management. Handles conversation CRUD, file uploads, streaming, tool invocation.

- `src/components/`: React components.
  - `chat/`: Core conversation UI.
    - `ArtifactPanel.jsx`: Side panel displaying HTML artifacts generated by the AI. Supports preview/code tabs, resize, fullscreen, copy, and share.
    - `ChatInput.jsx`: Text input with file upload (drag-drop, paste, select), image resize, multi-file preview.
    - `ChatLayout.jsx`: Main layout with resizable sidebar (conversation list, search, model selector), header with toggle buttons (thinking, artifacts, web search), and model dropdown.
    - `ContextUsage.jsx`: Ring chart showing context window usage.
    - `CustomLink.jsx`: External link with security confirmation dialog.
    - `MessageList.jsx`: Message rendering with Streamdown, thinking blocks, web search indicators, sources display, image/file attachments, streaming message display, and error display.
    - `ResponseMetrics.jsx`: Token count, duration, tokens/sec, and cost display.
    - `SettingsModal.jsx`: Full settings dialog with Connection/Models/Appearance/Behavior sections.
    - `ThinkingIndicator.jsx`: Animated bouncing dots indicator (sm/md/lg sizes).
  - `layout/AppWrapper.jsx`: Theme provider (next-themes) and TooltipProvider wrapper.
  - `ui/`: Low-level Shadcn UI primitives (avatar, button, card, dialog, dropdown-menu, input, label, scroll-area, select, separator, sheet, textarea, tooltip).

- `src/lib/`: Utility functions and client-side logic.
  - `api-client.js`: API wrappers for the chat endpoint. Contains `streamChatCompletion` (SSE-based streaming), `generateTitle`, Exa helpers (`exaSearch`, `exaFindSimilar`, `exaContents`, `exaAnswer`, `streamExaAnswer`), `streamChatWithTools`, and `executeToolCall`. API key management (`getStoredApiKey`, `setStoredApiKey`).
  - `artifacts.js`: HTML artifact extraction from ` ```html` fenced code blocks in text content. Supports streaming (unclosed fences) with `extractHtmlArtifacts`. Also exports `ARTIFACT_INSTRUCTIONS` for system prompts.
  - `bucky.js`: File upload client (`uploadFileToBucky` via `/api/upload` proxy) and `dataUrlToBlob` converter.
  - `db.js`: IndexedDB persistence layer for conversations. CRUD operations: `getAllConversations`, `saveAllConversations`, `putConversation`, `deleteConversation`.
  - `latex.js`: LaTeX delimiter normalization (`normalizeLatexDelimiters`) converting `\[...\]` and `\(...\)` to `$$...$$` format, and wrapping bare `aligned`/`align`/`align*` environments.
  - `model-pricing.js`: Fetches model pricing from Hack Club AI models endpoint with 5-minute cache. `getModelPricingMap` and `calcApiCost`.
  - `pricing.js`: Price formatting utility (`formatPrice`).
  - `tool-stream.mjs`: Helper for normalizing tool output from AI SDK stream parts (`getToolOutput`).
  - `tools.js`: Central tool registry (`TOOLS` array) with `web_search` (calls Exa Answer API via Hack Club proxy) and `javascript_calculator` (safe expression evaluator with tokenizer, Shunting-yard, RPN). Exports `executeTool`, `getTools`, `getToolExecutors`.

### File Upload & Storage (`src/lib/bucky.js`)
Files are uploaded via `/api/upload` which proxies to `bucky.hackclub.com`. The server validates file type (images, PDFs, text files up to 50MB) and sanitizes filenames. Returns a public S3 URL.

## Key Architectural Concepts

### 1. Streaming Chat
The `/api/chat` route uses `streamText` from the AI SDK with OpenRouter provider. It emits SSE events (`data: ...` format) with text deltas, reasoning deltas, tool call deltas, search results, and usage metrics. The client parses these in `streamChatCompletion`.

### 2. Tool Registry (`src/lib/tools.js`)
All tools defined in `TOOLS` array with JSON Schema parameters. Each tool has a corresponding executor:
- `web_search` — calls Hack Club AI's Exa proxy (`/proxy/v1/exa/answer`), returns answer + citations
- `javascript_calculator` — evaluates arithmetic using tokenizer → Shunting-yard → RPN

Both `/api/chat` (via AI SDK native tool calling) and `/api/tools` (standalone endpoint) use the same `executeTool` function.

### 3. Context Usage Counter
A ring chart in the header (`ContextUsage.jsx`) shows how much of the model's context window is consumed. The model list is fetched from `/api/models` on mount in `ChatLayout.jsx`, which populates a `contextWindowMap` keyed by model ID (from each model's `context_length` field). During streaming, the API route emits a `usage` event with `inputTokens`, which `page.js` passes to `ContextUsage` along with the max context length for the selected model. The ring fills up as input tokens accumulate and changes color at 75% (yellow) and 90% (red).

### 4. Artifacts System
The AI emits HTML inside ```html fenced code blocks. `ArtifactPanel` renders these in an iframe (preview tab) or syntax-highlighted (code tab). The system supports streaming (unclosed fences show a loading state).

### 4. State Management & Persistence
- **Conversations**: IndexedDB via `src/lib/db.js` with localStorage migration fallback.
- **Settings**: localStorage keys for API key, model selection, toggles, theme, metrics, etc.
- **Context**: Conversation title, messages, model, and artifact panel state are persisted per-conversation.

### 5. Search Page
`/search?q=...&search=true` renders the main chat page with an auto-sent initial query using web search enabled. Handled via `src/app/search/page.js`.

## Testing
The project uses **Vitest** and **React Testing Library** with jsdom environment.

### Test Structure
- `src/lib/__tests__/`: Tests for utility functions and business logic.
- `src/components/chat/__tests__/`: Tests for React components.
- `src/app/api/*/__tests__/`: Tests for Next.js API route handlers (route.test.js per endpoint).

### Commands
- `npm run test`: Run test suite (single run)
- `npm run test:watch`: Run in watch mode
- `npm run test:coverage`: Run with v8 coverage

### Key Guidelines
- **Model references in tests**: Use `qwen/qwen3.6-flash` for consistency (matches the app default).
- **Mocks**: Global mocks in `vitest.setup.jsx` for fetch, localStorage, navigation, theming, animation.
- **Isolation**: Use `vi.resetModules()` and `vi.useFakeTimers()` for tests relying on stateful module variables.

## Development Workflow

### Getting Started
1. `npm install`
2. `npm run dev`

### Code Quality
- `npm run lint` — Biome check
- `npm run format` — Biome format --write

### Coding Guidelines
- **Components**: Functional components with hooks. Shadcn UI patterns.
- **API Communication**: Use `src/lib/api-client.js` abstractions.
- **Styling**: Tailwind CSS exclusively, use `cn()` utility for conditional classes.
- **Error Handling**: API routes return structured errors, client parses via `getErrorMessage`.
- **No comments**: Keep code self-documenting; avoid inline comments.
